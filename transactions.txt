Each Propagation Type:

m2 method implements transaction

Propagation is an enum

> REQUIRED (join an existing transaction or create a new one if it does not exist)

- default type: Use it when you want multiple database operations to be part of the same logical unit of work (all succeed or all fail).

- @Service
public class OrderService {

    @Autowired
    private InventoryService inventoryService;

    // A new transaction (Train A) starts here
    @Transactional(propagation = Propagation.REQUIRED)
    public void placeOrder(Order order) {
        saveOrder(order);
        
        // inventoryService joins Train A. If it fails, the whole order rolls back.
        inventoryService.updateStock(order.getItems()); 
    }
}

@Service
public class InventoryService {

    // Joins existing transaction if called by placeOrder.
    // If called directly by a controller, it starts its own transaction.

    }

> SUPPORTS (supports if there is any active transaction, if not execute without
transaction)


- I'm easygoing. If you have a train, I'll ride it. If you're walking, I'll walk."
If a transaction exists, it runs inside it. If no transaction exists, it runs non-transactionally (every single SQL statement commits immediately).

- Read-only operations. If a method just fetches data, it doesn't strictly need a transaction. But if it's called in the middle of a massive data-update process,
 you might want it to share the same transaction to guarantee it sees the same "snapshot" of data as the rest of the process.

> MANDATORY (Require an existing transaction, if nothing found it will throw
an exception)

if any failure occurs within a method in which a method is marked with this
propagation, don't revert the changes for all just fail me


- The Rule: "I only ride trains. If you don't provide a train, I will throw a massive tantrum."
It requires an existing transaction. If none exists, it throws an IllegalTransactionStateException.

- When you have a helper method that manipulates highly sensitive state, and you want to enforce, at the architectural level, that no developer ever 
  accidentally calls this method outside of a transactional wrapper.








> REQUIRES_NEW (always create a new transaction suspending 
if any existing transaction)


- "I don't care about your train. I am pausing your train, building my own private train, riding it, and then you can resume your train."

- This always starts a completely new, independent transaction. If an outer transaction exists, it is temporarily suspended until the new transaction completes.

- @Service
public class OrderService {

    @Autowired
    private AuditService auditService;

    @Transactional(propagation = Propagation.REQUIRED)
    public void placeOrder(Order order) {
        try {
            processPayment(order);
        } catch (Exception e) {
            // Even though placeOrder rolls back, logFailure WILL commit
            // because it runs in its own independent transaction.
            auditService.logFailure(order.getId(), e.getMessage());
            throw e; 
        }
    }
}

@Service
public class AuditService {

    // ALWAYS creates a new transaction
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void logFailure(Long orderId, String error) {
        // ... save log to DB ...
    }
}
